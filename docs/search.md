# Search index

One Meilisearch document per product, written by Lunar's product indexing through the storefront's custom indexer (`config/lunar/search.php`, `indexers`). Drafts are indexed too because the admin panel searches the same index; the storefront always filters on `status = published` and `__soft_deleted = 0`. `scout.soft_delete` is true, so a soft-deleted product stays in the index with `__soft_deleted = 1` and its old status; `CatalogueSearch::filters()` is the only place that builds the filter, and the main query and every facet count query use it. A document written without `__soft_deleted` would not match, which Scout never does while `scout.soft_delete` is true.

- Searchable: `name`, `title`, `brand`, `key_points`, `safety_class`, `standards`, `skus` (so the admin panel finds products by SKU).
- Filterable: `collection_ids` (the product's collections and all their ancestors), `brand`, `safety_class`, `features`, `gender`, `standards`, `cut`, `toecap`, `colours_in_stock`, `sizes_in_stock`, `variants_in_stock` (colour and size pairs, e.g. `navy|9`), `in_stock` (bool), `price_min_ex_vat`, `status`. Prices are in pence, ex VAT.
- Sortable: `price_min_ex_vat`, `created_at`, `sort_order`.
- There is no inc VAT price field: the storefront is ex VAT only. Settings version 2 removed `price_min_inc_vat`. After deploying it, run `catalogue:sync-search-settings` and then reindex: the settings change drops the filter and sort entries, but existing documents keep the stale field until they are rewritten.
- Index settings are applied by the versioned command `php artisan catalogue:sync-search-settings`, run on every deploy. Never change them by hand.
- `php artisan catalogue:verify-index` (read-only, run after every import) checks the index against the database: missing and extra products, failed Meilisearch tasks and a sample of statuses and prices. What it expects is decided by Scout's own rule (`shouldBeSearchable()` over `Product::makeAllSearchableQuery()`), not by status.
- Listings and facets query Meilisearch only, through `App\Domain\Catalogue\Search\CatalogueSearch`. No direct Eloquent filtering for listings.
- `SCOUT_QUEUE=false` everywhere for now, production included: Scout sends documents to Meilisearch inside the request or command that changed the product. Queued indexing (`true`, with the Horizon `default` queue) is to be enabled later, after the first import, as a separate decision (docs/launch-checklist.md). Either way Meilisearch processes the documents asynchronously, so a document is searchable a moment after it is sent.
- Bulk writers (the ingestion module, seeders, imports) must wrap their writes in `withoutSyncingToSearch()` and then reindex the affected products in one batch afterwards. A stock or price change on a variant must result in its product being reindexed.
